# 独立发货清单

## 使用流程

入口为管理员“我的 → 发货清单”。粘贴发货文案后点击“识别为清单”，预览并修改货号、商品名、尺码规格、数量及备注，可增加或删除清单项。确认保存后按批次留存，逐项勾选完成；再次取消勾选可恢复待核对。详情显示完成项数和实际件数，提供编辑、刷新当前清单和原文回看；批次列表每页 10 笔。

这是独立的拣货核对记录，完成勾选不代表采购单已发货，不修改采购订单、发货信息、结款、库存、库存批次或流水。管理员共享可读写清单，采购员既不显示入口，也无法访问接口。

## 文案识别与核对

- 兼容当前“导出文案”的时间头、表头、`货号 商品名 尺码 ×数量` 与合计，支持 `x/X/*/＊` 数量标记及常见服装、鞋码。优先从规格与数量标记定位，不把货号中的 `X123` 识别为件数。
- 规则解析在浏览器执行，不调用大模型或外部服务。年份不明确的 `MMDD HH:mm:ss` 只保留原始时间文本，数据库录入/更新时间仍以服务器时间记录并按服务器时区展示。
- 不自动补全省略的名称、删除货号夹带的规格、合并相似货号或合并原文行。原文货号、名称保持可编辑；歧义通过提示供管理员核对。导出时货号等于名称而仅写一次的情况，预填为相同值并提示核对。
- “礼袋”等数量后缀作为清单项备注，保留在对应项，不推算礼袋数量，不把有无礼袋的商品混为一项。
- 空行和标准表头忽略，未识别行完整展示。原文合计与当前草稿件数不一致、或有未识别内容时，需手工补充/核对后确认，避免静默漏项；原始文案仍会一并保存。
- 当前示例可拆成 9 项、12 件，7 项带“礼袋”备注。限每批 1～200 项、原文 50000 字、标题 100 字、货号/名称各 300 字、规格 100 字、单项备注 500 字，数量为 1～100000 整数。货号或名称至少填写一个。

## 持久化与权限

迁移 `0021_shipping_checklists.sql` 新建独立表 `shipping_checklists`，保存标题、初次原文、原文时间、声明合计、JSONB 清单项、版本号、创建/修改人员及时间。清单项包含 `id/sku/title/size/qty/note/completed`，无采购订单和库存关联。创建后原文、原文时间及声明合计固定保留，编辑只改标题和清单项；不提供整批删除入口。

新建清单强制所有项为未完成，忽略客户端伪造完成状态。编辑时保留未修改项的完成状态；已修改内容、数量、规格或备注的项及新增项重置为未完成，需再次核对。删除项只影响这份清单。完成状态、编辑内容及对应审计同事务提交，任一步失败全部不生效。

所有写操作锁定清单行并核对版本号，防止多人同时勾选或编辑覆盖；版本陈旧返回 409，前端保留草稿/当前勾选供核对，显式刷新后重试。编辑期间不允许切换批次，取消前提示确认；收起面板保留当前组件草稿。刷新整个网页或离开“我的”页面会重置尚未保存的本地草稿。

## 接口与代码

- `GET /api/shipping-checklists?page=1`：数据库分页返回批次摘要，按创建时间和 ID 倒序；`GET ?id=...`：返回完整清单及原文。均要求管理员会话并禁用缓存。
- `POST /api/shipping-checklists`：创建，接收 `title/sourceText/sourceTimeText/declaredTotal/items`，返回 `{checklist}`。
- `PATCH /api/shipping-checklists`：`action="update"` 携带 `id/version/title/items` 编辑，或 `action="set-completed"` 携带 `id/version/itemId/completed` 勾选/恢复。写操作检查同源、管理员权限、类型、长度、数量和项目 ID 唯一性。
- `lib/shipping-checklist.ts`：共享类型、校验、进度汇总与规则解析。
- `app/shipping-checklist-panel.tsx` 与 CSS Module：管理员面板、草稿核对、历史分页、逐项勾选。
- `tests/shipping-checklist.test.mjs`、`tests/shipping-checklist-ui.test.mjs`、`tests/shipping-checklist.integration.mjs`：解析、界面及真实数据库事务/并发/权限/无订单库存联动验证。
