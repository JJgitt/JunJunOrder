# Agent 迭代手册

## 开始前

1. **每次迭代修改代码、配置或文档前必须同步远程代码**：先执行 `git status --short --branch`，再执行 `git pull --ff-only` 拉取当前分支上游，并确认成功后才开始修改。仅看本地 `origin/*` 或 CI checkout 不代表已同步。用户已有修改不覆盖、不混入提交，不得擅自 stash、reset、checkout 来完成拉取；拉取失败、无法快进或没有上游时停止修改并说明阻塞。仅查看、分析或回答问题无需拉取。同步后再查看相关源码、最近迁移和测试。
2. 写出这次改动涉及的角色、状态、数据表、API、UI、迁移与测试面。只修文档时也需核对链接和源码事实。
3. 写 Next.js 代码前先读仓库已安装版本在 `node_modules/next/dist/docs/` 下的相关指南；不要套用旧版本记忆。

## 改动矩阵

| 改动 | 必查位置 |
| --- | --- |
| 增减数据库字段 | `db/schema.ts`、新 `drizzle/NNNN_*.sql`、中文 `COMMENT ON`、`scripts/bootstrap.mjs`、快照/API/UI/导出/测试/数据库设计 |
| 订单或库存规则 | `app/api/app/route.ts` 的事务和行锁、`inventory`/`inventory_lots`/`inventory_movements`、审计、结构/集成测试 |
| 新动作或权限 | `POST /api/app` 校验、`snapshot()` 裁剪、前端 `mutate()`、越权测试 |
| 图片或识图 | 上传大小/类型、对象键安全、订单归属、识别失败和人工核对、可选配置缺失行为 |
| 商品知识库或识图补全 | `product_knowledge` 的来源与去重、管理员权限、名称/货号匹配可信度、歧义候选、规格描述/名称兜底、录单人最终核对；`historical` 仅建议，`approved` 仅用于明确货号编码，管理员确认后标 `manual`；禁止把旧单金额、尺码、数量和物流复制到新单 |
| UI | `app/page.tsx`、相关样式、移动端触摸输入、管理员/采购员双视角 |
| 部署 | `.github/workflows/ci-cd.yml`、`deploy/ci/`、镜像 digest、回滚兼容、生产健康检查 |

迁移以现有最大编号之后顺序新增，不能修改已执行文件；先检查 `drizzle/meta/_journal.json` 与手写迁移的编号关系，避免 `drizzle-kit generate` 撞号。新字段补中文注释，历史数据回填应先于非空约束。数据库和上传卷需要同一时间窗口备份；不要把备份放进仓库。

## 验证阶梯

文档改动：检查相对链接、文件路径、命令与当前源码吻合，并确认无秘密/生产数据。代码改动：按相关性运行 `npm run lint`、`npx tsc --noEmit`、`npm test`；涉及迁移或事务时用 PostgreSQL 集成测试验证。CI 的完整测试命令以 `.github/workflows/ci-cd.yml` 为准，本地 `npm test` 不是整条 CI 的替代。

## 交付与线上安全

遵循仓库根目录 `AGENTS.md`：相关本地检查通过后，只提交本次文件，推送 `main` 并观察现有 CI/CD 直到生产部署成功；用户明确要求本地、不部署或仅审查时例外。CI 失败时先保证现有生产容器持续运行，再在本次范围内修复或说明阻塞。数据库迁移要向后兼容：自动回滚镜像不会自动回滚数据库。

生产凭据只放环境变量或 GitHub Secrets；不得打印、写入 Wiki 或提交。运维备份、重置密码和服务器权限变更均须与功能迭代分开明确处理。
