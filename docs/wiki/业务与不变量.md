# 业务与不变量

## 角色与订单生命周期

游客可申请采购员账号；管理员审批后才可登录。采购员只管理本人可见订单，管理员执行审核、库存、发货、结款、导出和成员管理。权限应在服务端实现，不能只靠隐藏按钮；订单列表 Excel 导出也必须由服务端重新验证管理员身份和订单 ID。

订单头 `purchase_orders` 包含采购、审核、入库和结款信息；`order_items` 保存一单中的各商品与独立发货信息。流程为 `待审核 → 在途 → 已入库`，驳回可修改重提。订单入库后，数据库原始 `status` 仍为 `已入库`；管理员快照根据商品 `shipped_at` 派生 `待发货/已发货`，采购员快照继续显示 `已入库`。涉及状态判断时先分清数据库值与展示值。

## 必须保持的约束

- 金额持久化为整数“分”，API/UI 转换为“元”；禁止直接持久化浮点金额。
- 管理员看板的本月统计以服务器时区的自然月为准：月采购额按订单录入时间汇总未驳回采购单的整单实付金额；月销售额按商品行首次发货时间汇总已填写的预估售价；月利润（估）为这些已填售价商品行的预估售价减对应采购实付成本，可为负数。未填售价的已发货商品不计入销售与利润，并在界面提示件数；商品行金额已是整行合计，不再乘数量。
- 非空平台订单号的唯一性、最大商品数和批量上限，应以当前迁移和服务端校验为准。每单最多 20 个商品，超限应明确拒绝而不是截断；金额和数量须为可存入 PostgreSQL `integer` 的有限值；同一请求不得重复提交相同商品行 ID，以免重复更新库存。新增并发路径要保留唯一索引与冲突处理。
- 入库按整单执行；发货按商品行执行。`inventory` 汇总、`inventory_lots` 批次、`inventory_movements` 流水必须在同一事务内协调更新。入库为正流水，发货为负流水，撤销入库为调整流水。管理员编辑已入库商品时，移除批次应追加负调整流水；变更批次的货号、尺码或数量应追加原批次负调整与新批次正入库流水，不得改写或删除历史流水，也不得按货号、尺码批量影响同单其他商品行。
- 已发货商品不得再次扣库存；编辑已发货商品、删除订单或撤销入库时必须先检查相关批次和发货状态。
- 管理员订单详情的流转记录按商品行的首次 `shipped_at` 展示发货节点，部分发货也逐项记录；发货与结款事件按实际时间排列。修改发货物流不生成新的发货节点，也不改首次发货时间。采购员快照不返回发货字段，详情不展示发货节点。
- 采购结款与发货是独立维度：入库后可结款；结款后不得重复结款或撤销入库。实际金额可单独维护；批量结款不逐笔记录实际金额和截图。
- 首次结款和已结款后的补传/更换截图均自动识别金额，回填后允许人工修改，确认保存才生效。补传/更换时默认显示已有金额，识别失败保留当前金额；留空可清除金额。截图元数据、金额变更及审计在同一数据库事务保存，不改变结款时间、结款人或发货状态；未提交金额字段的旧客户端只更新截图。
- 图片存储于服务器持久化目录，表中只存元数据/对象键。读取必须通过鉴权接口并校验订单归属；结款凭证权限要按对应接口单独核对。
- 管理员与采购员快照字段不同；新增字段时审视隐私裁剪、CSV、图片接口与审计详情，避免泄露价格、库位或个人资料。
- AI 识图是表单辅助输入。不能把识别结果作为已确认事实；缺失字段不可凭空编造，提交前需用户核对。
- 商品知识库仅记录商品资料（标准名称、货号、别名及来源），由管理员维护，并可从审核通过的采购单积累。识图后只能利用这些资料补全商品名称和货号；历史订单的数量、尺码、金额、物流及订单号不得带入新单。迁移回填的历史资料标为 `historical`，仅能作为人工选择的候选；它们可能包含旧单的规格描述兜底，不能直接触发自动补全。新审核订单只有明显是货号编码的值才标为 `approved`；描述性规格仍保持 `historical`，等待管理员确认。管理员手工创建或编辑后标为 `manual`。只有 `approved`、`manual` 在高可信、无歧义时才可自动补全。
- 识图匹配有足够依据且候选明确时可在录单草稿自动补全；有多个可能商品时应展示候选供人选择；没有可靠资料时保留识图原值，并沿用“规格描述 → 商品名称”的原有货号兜底。最终仍由录单人核对，管理员审核。
- 管理员看板注意事项以 `completed_at` 记录实际划掉时间；已完成事项在原事项日期下方按服务器时区展示完成时间，未完成事项不显示完成时间。未完成事项持续展示，已完成事项只在划掉后的 7 天内返回，编辑内容或事项日期不能延长保留期。

## 关键流程的源码入口

- 录单/重提/审核：`app/api/app/route.ts` 中 `create-order`、`resubmit-order`、`approve`、`reject`。
- 商品知识库：`db/schema.ts` 的 `product_knowledge`、管理员商品资料动作、`app/api/orders/recognize/route.ts` 的识图后匹配，以及 `app/page.tsx` 的录单候选与资料管理界面。
- 入库/撤销：同文件 `receive`、`revert-receive`；需核对库存三个表。
- 发货：`ship`、`update-shipping`、`batch-ship`；更新已发货物流不应再扣库存。
- 结款：`settle-order`、`batch-settle`、`update-settlement-amount`，并检查 `app/api/settlements/**`。
- 成员与事项：`review-user-application`、`set-user-role`、`set-user-active`、`delete-user` 与 `*-dashboard-notice`。

更完整的业务背景见 [系统知识库](../系统知识库.md)；如其规则和当前源码不一致，以当前实现为准并修正文档。
